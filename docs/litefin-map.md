## chrome
Litefin's left rail (`docs/litefin-look.md` 3) on every page whose `chrome()` is `Chrome::TabBar` (registry.rs: Home, Library, Search, Favorites, the Content pages, Settings). The global clock rides with it; the sign-in pages show only the clock.
- Data: app/chrome.rs `ChromeSnapshot`: the nav items in Litefin's order (Home, Favorites, Search, Random, Libraries, Settings; Libraries only while the directory lists a library), the account avatar last, and one Libraries-popover row per directory section. Keys are `STRIP_BASE + stable id` (fixed per item, interned per section), so a library leaving renumbers nothing. `members()` publishes `StripMember`s: the column in group `tabs::STRIP`, the open popover's rows in `tabs::POPOVER`.
- Capture: bridge.rs `capture_chrome`, every frame, for `dispatch::rail_entry` (the Settings surface while it is up, else the top page): members, `strip_active` (the page's own item), `strip_fallback` (Home), the library on screen (the top page's, under Settings too) and the popover's lifetime (open only while focus is on one of its rows).
- Render: widgets.rs rail region: `RailRender` (owned by `Bridge.rail`; a spring per slot and per row plus the popover's opening), `rail_item_rect`, `rail_label_rect`, `rail_popover_rect`, `rail_row_rect`, the avatar and the clock. Transparent ground, no glass. `Rig::draw_chrome` paints it at Z::CHROME above the page.
- Focus: the dispatcher is the one door (dispatch.rs `PageWithStrip`, `chrome_dir`, `enter_rail`, `leave_rail`, `chrome_back`); no screen links to the rail. A LEFT the page has no answer for enters it on the page's own item, UP/DOWN walk the column and stop at its ends, RIGHT and BACK return to the seat the LEFT came from. In the popover, UP past the first row, DOWN past the last, LEFT and BACK close it onto the Libraries item; RIGHT goes nowhere. A page opts out with `Screen::strip_reachable()` (Settings below its root).
- Activation: OK or a click on a rail key never reaches the page: `Rig::strip_activate` queues it and `bridge::chrome_requests` answers it after the frame (`rail_activate`, one arm per control). Destinations are `NavOp::SelectTab` peers of Home; Libraries opens the popover on the library on screen; a row opens that library (a teleport on the Library page, else a Library page seeded with the section) and hands focus back to the Libraries item; Random opens a random title's detail page; Settings presents the Settings surface; the avatar opens the account menu. Over Settings, every control but the Settings and Libraries items dismisses it first.
- Pointer: the dispatcher publishes the rail's stops from the members (Hover::Focus while the page is strip_reachable); the open popover's opener is Hover::Ignore, so the pointer can cross it to the rows.
- Dev triggers `rail`, `favorites`, `random`, `library`: docs/litefin-shots.md.

## upstream_rules
From AGENTS.md, ui/CLAUDE.md, screens/CLAUDE.md, docs/DESIGN.md:
